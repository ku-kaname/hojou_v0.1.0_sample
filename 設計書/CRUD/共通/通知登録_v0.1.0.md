### 処理概要

#### 【目的】
- 通知を1件登録する（F08）。設計書「サーバー処理（main）/共通」の通知生成から呼び出される。

#### 【処理概略】
- notificationテーブルへ1件追加し、`flush`する（`commit`は呼び出し元が行う）。日次通知（`due_soon`・`overdue`）は、同日に登録済みの場合は登録せず読み飛ばす。

## ○処理詳細

### 1. 通知レコードの登録

- (1) 以下のフィールドを設定した通知レコードをDBに登録して`flush`する。

  | 論理名 | 設定値 | 備考 |
  |---|---|---|
  | 内部ID | 自動採番 | - |
  | 宛先（ユーザー内部ID） | 入力値．宛先（ユーザー内部ID） | - |
  | 種別 | 入力値．種別 | - |
  | 関連申請（内部ID） | 入力値．関連申請（内部ID） | - |
  | 既読フラグ | FALSE | - |
  | 作成日時 | サーバー時刻 | DBの既定値 |
  | 通知日 | 入力値．通知日 | - |

- (2) 登録方法を種別で切り替える。

  | 条件 | 登録方法 |
  |---|---|
  | 入力値．種別が`due_soon`または`overdue` | `INSERT ... ON CONFLICT DO NOTHING`（一意インデックス`uq_notification_daily`に違反する場合は登録しない）。登録しなかった場合は戻り値を偽とする |
  | 上記以外 | 通常の`INSERT`（常に登録する） |
