### メソッド名

| 項目 | 内容 |
|---|---|
| メソッド論理名 | 備品編集 |
| メソッド物理名 | update_equipment_endpoint |
| サービス層メソッド論理名 | 備品編集処理 |
| サービス層メソッド物理名 | `services.update_equipment_admin` |

- 本書の「処理詳細」は、エンドポイント層（main）とサービス層（services）を通して記載する。エンドポイント層は入力の受付・検証済み値の引き渡し・HTTPレスポンス化のみを行い、業務処理はサービス層メソッドで行う（設計書「アーキテクチャ方針」参照）。

### 処理概要

#### 【目的】
- 管理者が備品の内容を更新する。有効フラグによる無効化・再有効化を含む。資産番号は変更しない。

#### 【処理概略】
- 備品を行ロックして取得し、無効化時は未完了の申請がないことを検証したうえで更新する。

## ○処理詳細

### 1. 対象備品の取得とロック（サービス層 `update_equipment_admin`）

- (1) 現在日時を取得する（→ サービス層 `get_now`）。

- (2) 備品を内部IDで行ロックして取得する（→ CRUD「備品内部ID指定取得」。備品内部ID=入力値．備品内部ID、行ロック要否=True）。

  - 貸出申請・承認・貸出の各処理も同じ備品の行ロックを取得するため、無効化と申請・承認が競合しても整合が保たれる。

  | 条件 | 例外 | ステータスコード | エラー内容 |
  |---|---|---:|---|
  | 取得できない | HTTPException | 404 | "備品が見つかりません" |

- (3) 無効化に該当する場合、未完了の申請がないことを検証する。

  | 判定名 | 条件 |
  |---|---|
  | 無効化 | (2)の備品の有効フラグが真 かつ 入力値．備品編集リクエスト．有効フラグが偽 |

  | 条件 | 動作 |
  |---|---|
  | 無効化に該当する | 未完了の申請件数を取得する（→ CRUD「備品未完了申請件数取得」。備品内部ID=入力値．備品内部ID）。件数が1以上の場合、HTTPException 400 "申請中・承認済み・貸出中の申請がある備品は無効化できません" を送出する |
  | 上記以外（再有効化・内容のみの更新を含む） | 何もしない |

- (4) 備品を更新する。

  **呼出先**

  | 項目 | 論理名 | 物理名 |
  |---|---|---|
  | クラス | データアクセス層 | crud |
  | メソッド | 備品情報更新 | update_equipment |

  **引数**

  | 引数 | 型 | 必須 | 設定値 | 備考 |
  |---|---|:---:|---|---|
  | データベース | `Session` | ○ | 入力値．データベース | - |
  | 備品情報 | `Equipment` | ○ | (2)の備品 | - |
  | 備品名 | `str` | ○ | 入力値．備品編集リクエスト．備品名 | - |
  | 分類 | `str` | ○ | 入力値．備品編集リクエスト．分類 | - |
  | 説明 | `str` | ○ | 入力値．備品編集リクエスト．説明 | - |
  | 保管場所 | `str` | ○ | 入力値．備品編集リクエスト．保管場所 | - |
  | 有効フラグ | `bool` | ○ | 入力値．備品編集リクエスト．有効フラグ | - |
  | 現在日時 | `datetime` | ○ | (1)の現在日時 | - |

- (5) 貸出中の申請を取得する（→ CRUD「貸出中申請取得」。備品内部ID=入力値．備品内部ID）。

  - 再有効化・内容のみの更新の場合でも貸出中の申請は存在しうる（無効化されていない備品）ため、常に取得して返却に反映する。

- (6) 今日の日付（JST）を取得する（→ サービス層 `get_today`）。

- (7) コミットする。
