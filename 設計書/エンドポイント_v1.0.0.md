## 共通事項

- すべてのパスは`/api`配下とする（例：`/api/auth/login`）。認証・認可・エラー応答の共通ルールは設計書「アーキテクチャ方針」に従う。
- 「認証」列の意味は下表のとおり。

| 認証 | 意味 | 使用する検証関数 |
|---|---|---|
| 不要 | 認証不要 | なし |
| 要Bearer認証（初期パスワード可） | ログイン済みであれば初期パスワード未変更でも利用可 | 現在ユーザー取得 |
| 要Bearer認証 | ログイン済み・初期パスワード変更済み | 有効ユーザー検証 |
| 要Bearer認証（管理者のみ） | 管理者ロールのみ | 管理者権限検証 |

## エンドポイント一覧

### 認証・ユーザー管理（設計（認証・ユーザー管理））

| 機能 | HTTPメソッド | エンドポイント | 認証 | 備考 |
|---|---|---|---|---|
| F01 ログイン | POST | `/api/auth/login` | 不要 | ユーザーID・パスワードでトークンを発行する。連続失敗によるロックあり |
| F01 ログアウト | POST | `/api/auth/logout` | 要Bearer認証（初期パスワード可） | トークン世代を進めて発行済みトークンを失効させる |
| F02 パスワード変更 | PUT | `/api/users/me/password` | 要Bearer認証（初期パスワード可） | 変更後に新しいトークンを返却する（旧トークンは失効） |
| （共通）自分の情報取得 | GET | `/api/users/me` | 要Bearer認証（初期パスワード可） | ロール・初期パスワード変更要否を返却する。画面の表示制御用 |
| F16 ユーザー一覧取得 | GET | `/api/admin/users` | 要Bearer認証（管理者のみ） | 無効化済みを含む。ページング・キーワード絞り込み |
| F16 ユーザー登録 | POST | `/api/admin/users` | 要Bearer認証（管理者のみ） | 初期パスワードを管理者が設定する |
| F16 ユーザー取得 | GET | `/api/admin/users/{user_id}` | 要Bearer認証（管理者のみ） | パスは内部ID |
| F16 ユーザー編集 | PUT | `/api/admin/users/{user_id}` | 要Bearer認証（管理者のみ） | 氏名・所属・ロール・有効フラグ（無効化・再有効化）を更新する |
| F16 パスワード初期化 | POST | `/api/admin/users/{user_id}/reset-password` | 要Bearer認証（管理者のみ） | 初期パスワードを設定し、初回変更要とする |

## パスの設計上の注意

- 固定パス（`/api/equipments/categories`・`/api/equipments/import`・`/api/loan-requests/me`・`/api/admin/loan-requests/overdue`・`/api/admin/loan-history/export`・`/api/notifications/summary`・`/api/notifications/read-all`）は、同階層のパスパラメーター付きパスより先に登録する（先に登録しないとパスパラメーターに解釈される）。
- 機能を担当する設計書の分担は、見出し（機能群）のとおり。共通設計（設計（共通））は、各機能群が参照する本一覧・テーブル定義・共通スキーマ・共通認可処理・通知生成を担う。
