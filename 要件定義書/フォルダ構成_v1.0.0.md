## フォルダ構成

アプリケーション本体（`frontend/`・`backend/`以下）および開発プロセス成果物の構成を示す。`hojou/`・`.claude/`・`.agents/`・`AGENTS.md`・`CLAUDE.md`等の開発プロセス運用に関するファイルはプロジェクト横断的な構成のためここには含めない。`{バージョン}`は成果物のバージョン（`vMAJOR.MINOR.PATCH`）を表す。

```
.
├── docker-compose.yml                # フロントエンド・バックエンド・DBコンテナの起動定義
├── README.md                         # プロジェクト概要・セットアップ・運用手順
├── .env.example                      # 環境変数のひな形（実際の.envはGitに含めない）
│
├── frontend/                         # フロントエンド本体（React・TypeScript）
│   ├── Dockerfile                    # Nginx配信用のマルチステージビルド
│   ├── nginx.conf                    # 静的配信・/api中継・HTTPS設定
│   ├── package.json
│   ├── tsconfig.json
│   ├── vite.config.ts
│   ├── index.html
│   └── src/
│       ├── main.tsx                  # エントリーポイント
│       ├── App.tsx                   # ルーティング定義（ロール別ガード）
│       ├── api/                      # バックエンドAPI呼び出し関数
│       ├── pages/                    # 画面単位コンポーネント（S01〜S11に対応）
│       ├── components/               # 画面共通の部品
│       ├── types/                    # APIリクエスト・レスポンスの型定義
│       └── tests/
│           └── unit/                 # 単体テストコード（Vitest + React Testing Library）
│
├── backend/                          # バックエンド本体（Pythonパッケージ）
│   ├── Dockerfile
│   ├── pyproject.toml
│   ├── alembic.ini
│   ├── migrations/                   # Alembicマイグレーション
│   └── app/
│       ├── __init__.py
│       ├── main.py                   # エンドポイント定義（オーケストレーション層の呼び出しのみ）
│       ├── services.py               # オーケストレーション層（申請の状態遷移・重複判定・通知生成等の業務処理）
│       ├── auth.py                   # JWT認証・パスワードハッシュ・ロール判定
│       ├── crud.py                   # DB操作関数（Create / Read / Update / Delete）
│       ├── models.py                 # SQLAlchemyテーブルモデル（USER / EQUIPMENT / LOAN_REQUEST / NOTIFICATION）
│       ├── schemas.py                # Pydanticスキーマ
│       ├── database.py               # DB接続・セッション管理
│       ├── scheduler.py              # 日次処理（期限通知・ノーショー自動取消）の起動定義
│       └── tests/
│           ├── __init__.py
│           ├── conftest.py
│           ├── unit/                 # 単体テスト（DBに依存しない）
│           └── integration/          # 結合テスト（PostgreSQLを使用）
│
├── test_specification/               # テスト仕様書
│   ├── unit_test_specification/      # 単体テスト仕様書（evidence/を含む）
│   └── integration_test_specification/ # 結合テスト仕様書（evidence/を含む）
│
├── 作業管理/                          # バックログ・タスク管理
├── 引継ぎ資料/                        # 機能別・タスク毎の引継ぎ資料
│
├── 要件定義書/
│   ├── 概要_v{バージョン}.md
│   ├── 業務要件_v{バージョン}.md
│   ├── 機能一覧_v{バージョン}.md
│   ├── 機能要件_v{バージョン}.md
│   ├── 非機能要件_v{バージョン}.md
│   ├── 技術スタック_v{バージョン}.md
│   ├── 判断根拠書_v{バージョン}.md
│   ├── フォルダ構成_v{バージョン}.md  # 本ファイル
│   └── 画面一覧_v{バージョン}.md
│
├── 設計書/                            # 設計工程で機能群ごとにフォルダを分けて格納
│   ├── エンドポイント_v{バージョン}.md
│   ├── テーブル定義（models）_v{バージョン}.md
│   ├── 画面/UI仕様書/
│   ├── CRUD/<機能群>/
│   ├── サーバー処理（main）/<機能群>/
│   ├── スキーマ（schemas）/
│   └── 認証・認可（auth）/
│
└── レビュー指摘表/                     # 各工程のレビュー指摘管理
    └── 要件定義工程/                   # 要件定義書と同じフォルダ構成で格納
```

- 機能群（設計工程以降の分割単位）は設計工程の着手時に決める（暫定案：認証・ユーザー管理／備品管理／貸出申請・承認／貸出・返却・履歴）。
