# 概要

社内の備品（PC・プロジェクター等）の貸出を管理するWebアプリです。社内LANに接続した社内端末のWebブラウザから利用します（社外からの利用は対象外）。

- **一般社員**：備品の検索、空き状況の確認、貸出申請（将来日の予約を含む）、申請の取消、自分の申請・貸出状況の確認、アプリ内通知の確認
- **管理者**：一般社員の操作に加えて、申請の承認・却下、貸出・返却の記録、期限超過の確認、備品・ユーザーの管理（CSV一括登録を含む）、貸出履歴の閲覧・CSV出力

メール・チャットツール等の外部通知や、社内SSO連携は行いません（ログインは本システム独自のユーザーID・パスワードです）。

| 区分 | 技術 |
|---|---|
| フロントエンド | TypeScript / React / Vite / React Router、配信はNginx（HTTPS終端・`/api`の中継） |
| バックエンド | Python 3.12 / FastAPI / SQLAlchemy / Pydantic / APScheduler（日次処理） |
| データベース | PostgreSQL 16（マイグレーションはAlembic） |
| 認証 | JWT、パスワードはArgon2idでハッシュ化して保存 |
| 起動方式 | Docker Compose（db・backend・frontendの3コンテナ） |

# セットアップ

## 1. 事前に用意するもの

- Docker と Docker Compose（サーバーにインストール済みであること）
- HTTPS用の証明書ファイル2つ（社内サーバーで使うもの。ファイル名は次のとおり固定）
    - `server.crt`（証明書）
    - `server.key`（秘密鍵）

## 2. 設定ファイル（.env）の作成

リポジトリ直下の `.env.example` をコピーして `.env` を作成し、値を設定します。`.env` にはパスワード・秘密鍵が入るため、**Gitへコミットしたり他人に共有したりしないでください**。

| 変数名 | 内容 |
|---|---|
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | データベースのユーザー名・パスワード・DB名（自由に決めてよい。パスワードは推測されにくいものにする） |
| `JWT_SECRET_KEY` | ログイン情報（トークン）の署名に使う秘密鍵。**32文字以上**のランダムな文字列にする。未設定・32文字未満だとバックエンドは起動しない |
| `INITIAL_ADMIN_LOGIN_ID` | 最初の管理者のユーザーID（3〜32文字。半角英数字・`_`・`-`） |
| `INITIAL_ADMIN_PASSWORD` | 最初の管理者の初期パスワード（8〜128文字） |
| `ENABLE_API_DOCS` | `1` にするとAPI仕様書の画面を公開する。運用時は未設定（無効）のままにする |
| `TLS_CERT_DIR` | 証明書を置くフォルダ。未設定なら `./certs` |

ランダムな秘密鍵の作り方の例：

```
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 3. 証明書の配置

`TLS_CERT_DIR`（既定は `./certs`）のフォルダに `server.crt` と `server.key` を置きます。

## 4. 起動

```
docker compose up -d --build
```

- 初回起動時にデータベースのテーブルが自動で作成され、`.env` で指定した初期管理者が自動作成されます（すでに管理者がいる場合は作成されません）。
- 停止は `docker compose down` です（データは `db_data` ボリュームに残ります）。**`docker compose down -v` はデータベースの中身がすべて消えるため実行しないでください。**

# 使用方法

## ログイン

1. ブラウザで `https://<サーバーのアドレス>/` を開きます（`http://` でアクセスしても案内されます）。
2. 管理者が発行したユーザーIDとパスワードでログインします。
3. **初期パスワード（管理者が発行・初期化したパスワード）でログインした場合は、先にパスワード変更画面でパスワードを変更する必要があります。** 変更するまで他の機能は使えません。
4. パスワードを5回連続で間違えると、アカウントが15分間ロックされます。

## 一般社員の使い方

| やりたいこと | 操作 |
|---|---|
| 備品を探す | 「備品一覧」で分類・キーワードで検索。貸出可・貸出中・返却予定日を確認できる |
| 貸出を申請する | 備品を選び、「備品詳細・貸出申請」で予約状況を確認して、開始日・返却予定日・用途を入力して申請 |
| 申請を取り消す | 「自分の申請一覧」で、貸出前（申請中・承認済み）の申請を取消 |
| 状況を確認する | 「ホーム」で通知・自分の貸出中・期限超過を確認。承認・却下・取消の結果と返却期限が近い／超過した貸出が通知される |
| パスワードを変える | 「パスワード変更」から変更 |

申請は、承認されると期間の予約が確定します。承認済みの申請は、開始日以降（返却予定日まで）に管理者が「貸出処理」を行うと貸出中になります。開始日を過ぎても承認・却下されなかった申請中の申請と、返却予定日を過ぎても貸出されなかった承認済みの申請は、毎日6:00（日本時間）の日次処理で自動的に取消になります。

## 管理者の使い方

管理者は、一般社員の操作もすべて行えます。加えて次の操作ができます。

| やりたいこと | 操作 |
|---|---|
| 申請を承認・却下する | 「申請管理」で申請中の申請を承認、または却下（理由が必須）。承認時に期間の重複を再確認する |
| 貸出・返却を記録する | 「申請管理」で、承認済みの申請に「貸出処理」、貸出中の備品に「返却処理」（返却日時・状態メモ） |
| 承認済みの申請を取り消す | 「申請管理」で理由を入力して取消（備品の故障など） |
| 期限超過を確認する | 「期限超過一覧」で返却予定日を過ぎた貸出を確認 |
| 備品を管理する | 「備品管理」で1点ずつ登録・編集・無効化（再有効化も可）。CSVファイルから一括登録もできる |
| ユーザーを管理する | 「ユーザー管理」で登録・編集・無効化（再有効化も可）、ロール（一般／管理者）の設定、パスワード初期化 |
| 貸出履歴を調べる | 「貸出履歴」で全社員の履歴を検索・閲覧し、CSV出力 |

- 貸出・申請の履歴は削除されません。備品・ユーザーは「無効化」（削除ではなく使えなくする）で扱います。
- 最後の有効な管理者は、無効化や一般ロールへの変更ができません。
- 備品のCSV一括登録は、UTF-8のCSVファイルを使い、1回の登録は最大1,000行・5MBまでです。1行でも内容に誤りがあると1件も登録されず、誤りのある行と内容が画面に表示されます。

# 開発者向け情報

## テストの実行

バックエンド（PostgreSQLを別途用意し、テスト用DBの接続先を環境変数で指定します）：

```
cd backend
pip install -e ".[dev]"
TEST_DATABASE_URL=postgresql+psycopg://<ユーザー>@<ホスト>:<ポート>/<テスト用DB名> python -m pytest
ruff check app
```

- テスト用DBには拡張機能 `btree_gist` が必要です（テーブル作成時に使用します）。
- 単体テスト・結合テストを合わせて384件が対象です。

フロントエンド：

```
cd frontend
npm install
npm run test
npm run lint
npm run build
```

## フォルダ構成

| フォルダ | 内容 |
|---|---|
| `backend/` | バックエンド（`app/`にアプリ、`migrations/`にDBマイグレーション、`app/tests/`にテスト） |
| `frontend/` | フロントエンド（`src/`に画面、`nginx.conf`にNginx設定） |
| `要件定義書/`・`設計書/` | 要件定義書・設計書 |
| `単体テスト仕様書/`・`結合テスト仕様書/` | テスト仕様書（実施結果を含む） |
| `レビュー指摘表/` | 各工程のレビュー指摘表 |
| `引継ぎ資料/` | 機能別・タスク毎の引継ぎ資料（改修時は、まず`機能別/`を参照） |
| `作業管理/` | バックログ・タスクの管理資料 |

# 自由記述

## セキュリティ上の注意

- パスワード・秘密鍵・トークンは、ログにも画面にも出力しません。`.env` は共有しないでください。
- 通信はHTTPS（TLS 1.2以上）です。証明書の管理・更新はサーバー管理者が行ってください。
- データベースはコンテナ内部のネットワークでのみ接続されます（外部へは公開していません）。

## 制約・未対応事項

- 貸出期間の延長申請、消耗品の数量管理、メール等の外部通知、社内SSO連携、備品写真のアップロードには対応していません。
- `TLS_CERT_DIR` に、`docker-compose.yml`が読み込めない場所（Docker Desktopで共有されていないフォルダ等）を指定すると、証明書を読み込めず起動に失敗します。
- 日次処理（期限通知・自動取消）は、バックエンドを1プロセスで動かす前提です（`docker-compose.yml`のとおり、変更しないでください）。
